# 执行计划与恢复

## 生成计划

复制 `assets/migration-plan.example.json` 到任务工作目录，填写本机核实的绝对路径。每个应用或独立数据目录一份计划；多份计划顺序执行，前一份失败先处理，不并行迁移。

字段含义：

- `source`、`destination`：实际源/目标目录，不能是同一物理目录，也不能相互嵌套。父级联接也算物理重叠。整个用户目录、AppData、Windows、Program Files 等根目录不使用本引擎整体迁移。
- `recovery_root`：独立恢复目录，位于两个数据树之外，与目标同一卷，便于同名冲突文件原子归档。源可以在另一卷。
- `approved_existing_backups`：只填写本次已核实、授权处理的既有旧备份绝对路径。计划模式会列出发现的备份；发现符合命名格式并不自动授权删除或恢复它。执行中本次刚创建的备份由当前计划授权，中断后重跑则先复核现状并填写此白名单。
- `policy.conflicts`：默认 `stop`。只有用户明确以当前源为权威、允许归档冲突的目标版本时才选 `archive-source-wins`。这不会合并两个不同的数据库；目标旧文件会保存在恢复目录中。
- `policy.cleanup_source_backup`：明确填写布尔值。`false` 会保留旧源副本，不应声称释放了这些空间；`true` 才在归档及复核成功后清理旧源。用户已经要求搬走并释放空间时可在授权范围内设置为 `true`，不反复索要同一授权。
- `processes.main_names`：核实的主进程名，不带 `.exe`，精确匹配。不能把有未保存内容的主程序登记为 helper。
- `blocked_executable_roots`：应用安装目录等依赖进程路径，不要填整个磁盘、所有 Program Files 等过宽范围。
- `helpers`：默认空数组。确有残留后台时，按下例加入精确进程名与核实的二进制根目录；空路径或未知路径只会阻止迁移，不能按 PID 猜测强杀。

```json
{"names": ["sandbox-cli-gc"], "executable_roots": ["D:\\Programs\\ExampleApp\\resources\\sandbox"]}
```

此配置是格式示例，不代表该程序已被核实。

## 运行

使用位于迁移源之外的 PowerShell 7。不要把运行中的解释器、引擎、计划或恢复目录放在要迁移的树内。不要为此把约 250 MiB 的 PowerShell 运行时打包进 skill。

```powershell
& "<独立的 pwsh.exe 绝对路径>" -NoProfile -ExecutionPolicy Bypass -File "<skill>/scripts/Invoke-StorageMigration.ps1" -PlanPath "<计划.json>"
```

默认仅校验计划并打印，不写文件、不停进程。准备好并处于用户授权的实际迁移范围时，加 `-Apply`；只有计划内 helper 可临时停止时加 `-StopBackground`。引擎不修改服务/计划任务启动方式；需要处理服务时，先核实其 ImagePath 和依赖，再在授权范围内设计临时停止及恢复，不能扩大 helper 名单来绕过检查。

引擎行为：哈希源和已有目标 → 默认拒绝同名不同内容的冲突（显式选择后可归档并采用源版本）→ 完整复制含链接本身 → 校验源、目标及目标独有数据 → 复核源未变化 → 原子重命名源 → 建立并验证联接 → 归档旧源 → 按计划清理。目标独有的任务目录、Claw、配置等始终保留原位；不使用镜像清除。

源文件即使长度、时间相同也可能内容不同，因此复制使用 `/IS /IT` 并最终比较 SHA-256。已有目标目录和独有任务的 ACL 不重置；新增目录和文件先按源 DACL 安全创建，再用 `/COPY:DAT` 填入数据，避免继承共享目标的更宽访问权限。旧源归档到新建私有恢复目录时用 `/COPY:DATS` 保留权限。两者均不用 `/COPYALL`，不申请所有者/审计特权。

物理目录重叠检查解析父级联接；同卷判断和空闲空间检查使用 Windows 实际卷标识和容量 API，而不是只比较盘符。指向其他卷的挂载点不能用盘符相同来冒充同卷。

## 中断与清理

- 复制或哈希失败：源不切换，保留目标和恢复文件；检查明细、进程及源变化后再执行。安全预创建或复制中断可能留下本次生成的空文件/部分副本；`conflicts=stop` 重跑仍会拒绝它们，不会擅自认定这些文件可覆盖。根据日志核实来源、保留目标独有数据；只有用户授权仍以源为权威时，才把计划显式改为 `archive-source-wins`，归档这些冲突后继续。不能为追求自动续传而绕过冲突策略。
- 源名称缺失且只有一个已在 `approved_existing_backups` 中复核的约定旧备份：恢复原名，再继续复制与验证。
- 联接创建或最终校验失败：应用仍关闭时恢复原名；若应用已经重启，保留现场及备份，避免丢弃新写入。
- 源已是正确联接且有旧备份：验证归档后按清理策略处理，不重搬活动数据。
- 清理失败：先判断是共享锁、只读属性、ACL 还是路径长度。可报告“文件迁移完成，旧副本清理未完成”，不能整体宣称清理成功。
- 已归档的旧源中出现当前账户 `DENY Delete/DeleteChild` 时，引擎只在白名单旧备份树内去掉这些删除拒绝位；保留其他拒绝规则，跳过重解析点目标。活动源/目标及恢复归档的权限不重置。其他账户或组的拒绝、占用、权限不足仍应停止，不递归 `takeown`、`icacls /reset` 或强行关闭未知进程。
- 原路径联接要保留。正常清理绝不是“先删除联接，再删除旧备份”。

恢复目录包含源归档、冲突目标文件和日志。发现功能问题时先关闭应用，比较活动目标与归档是否又有新写入，给出具体恢复计划；不要盲目把旧归档覆盖当前数据。

## 验收

逐项检查：原路径是预期联接、目标实际存在、旧源备份是否残留及大小、缓存实际路径、磁盘可用空间变化。文件逻辑大小与磁盘空闲增量不必相等，不能重复计算联接内容。

哈希验证只能证明文件复制。应用登录、浏览器密码/扩展、聊天历史、MCP、云盘同步、MATLAB 授权及自动更新都需要真正打开相应应用验证。不要因脚本退出码为 0 就宣称这些功能已通过。
